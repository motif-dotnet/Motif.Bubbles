# Motif Bubbles: decisions so far

Motif Bubbles draws a Motif app's architecture as it's built: a graph of bubbles, sized by code and ringed with Stryker's mutation results. It was designed in the [Motif Bubbles design note](https://github.com/motif-dotnet/.github/blob/main/design/bubbles.md), whose eight decisions still stand and aren't repeated here: what a bubble is, what the graph draws, scanning the code by Motif's conventions, rings from the report CI publishes to Pages, one snapshot, its own repo, and its name. The build is tracked in [motif-dotnet/.github#43](https://github.com/motif-dotnet/.github/issues/43). This file records what was decided while building it.

| # | Topic | Decision |
|---|---|---|
| 1 | Built the Motif way | The repo got its own `motif/` folder first: a sketch drafted for Motif Sketch, with the plan, diagrams and glossary exported from it. The solution was stubbed from the plan, as Motif Glossary's was. |
| 2 | Deep adapters | The adapters follow Motif's [deep adapters](https://github.com/motif-dotnet/.github/blob/main/design/adapters.md) rules from the start. The ports are `ForOpeningFolders` and `ForOpeningRepos`, and their adapters `ForOpeningFoldersViaPickerAndDrop` and `ForOpeningReposViaGitHub`. The folders adapter's Seam is `LocalFolders`, with the real Fitting `JsInteropLocalFolders` and the fake `FakeLocalFolders`; GitHub's Seam is the platform's `HttpMessageHandler`, faked by `FakeGitHub`. Only Fittings are faked, so every spec runs both real adapters. The real Fittings have manual checks in [docs/manual-checks.md](docs/manual-checks.md). |
| 3 | Spec names | Spec names read as propositions, after [Motif.Is](https://github.com/motif-dotnet/Motif.Is): a class names the subject and its methods finish the sentence (`A_folder.with_no_UseCases_project.is_not_a_Motif_app`). So spec classes have lower-case names, and `.editorconfig` turns off the warning about them (CS8981) in `Checks/`. |
| 4 | Fixtures | The specs draw a made-up repo, Motif.Tiny, small enough to check every bubble, link and ring. They also draw this repo's own code, so Motif Bubbles is a test fixture as well as the code under test, as the design note's decision 7 says. |
| 5 | Mapping the code | A project is named by its `.csproj`, so a project at the repo's root is mapped too. A fake shared by several ports, in a `Fakes` folder named for no port (as Motif Sketch's `FakeFiles`), sits in a last column of its own, Shared fakes, with an Extends link from each fake that builds on it, rather than as a stray fake. |
| 6 | Drawing | Bubbles are graded by lines of code, from a smallest size to the biggest the graph leaves room for. A name goes inside its bubble when it fits, broken at its spaces if need be, and under it when it doesn't. Inside, a bubble shows only what the rest of the graph doesn't: its count of specs or members. The mutation score and stats line are left out, as the size, the ring and the hover card already show them. The panel of layers and key starts closed, so the graph gets the whole width. |
| 7 | Shared look | Motif Bubbles uses the suite's web kit ([brand/web](https://github.com/motif-dotnet/.github/tree/main/brand/web)), copied in by `scripts/sync-suite.sh`, as the other tools do. It's in the kit's `Tools.All` after Sketch, tagged *preview* and *new* until the end of January 2027, so the app bar has the tool switcher, carrying a repo on screen to the other tools. It has link-preview tags and the social preview card from the brand folder, and counts visits with GoatCounter, as every Motif site does. |
| 8 | Browser specs | Playwright specs in `Checks/Motif.Bubbles.BrowserSpecs`, after Motif Glossary's (its decision 18), for what the specs over the User port can't see: the app bar fitting at 375, 637 and 1280 px on the start page, a repo link and a picked folder; the side panel starting closed, opening beside the graph or under it on a narrow screen, and closing; and both ways in, a folder picked in the real picker and a repo link. GitHub stands in as this repo's own code, and every other request is blocked. A folder is picked with the page 1280 px wide, then narrowed to the width being checked, as Edge on Linux won't open its picker in a window under 400 px wide. Each profile is traced, and CI keeps the traces when the browser specs fail. |
| 9 | Mutation testing | The specs are checked by [Stryker.NET](https://stryker-mutator.io/docs/stryker-net/introduction/), set up as Motif Glossary's (its decision 16): a .NET tool pinned in `dotnet-tools.json`, run over `Motif.Bubbles.Specs.slnx` so the browser specs stay out. It runs in CI on every push to main, beside the deploy, and the site then goes out again with its report at `motif/mutation-report.json` (the design note's decision 5), so Motif Bubbles draws its own rings. A low score doesn't fail the build. |

## Later (not v1)

From the design note and #43: run Stryker nightly instead of on every push, compare two snapshots, and decide whether it leads with risk or general stats once it has been used.
